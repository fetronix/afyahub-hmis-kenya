# Facility-billing rollback: pre-change audit

**Recorded before implementation, 31 October 2026.** The active feature branch was fast-forwarded from `0111b550` to the current `main`, `13814abc4c5ab87fa629398b52aeebb192d20c36`, with a clean working tree. That commit is the code recovery point. The last pre-master-catalogue tree is `0f30d3e33001d42c336f931ae69f7e4e67003b9c`, the parent of the PR #31 merge. PR #31 (`7576ddf`, merge `5e17348`) introduced the master catalogue and PR #32 (`a610919`, merge `13814ab`) introduced reviewed clinical selection. No production database, facility data, or credentials have been accessed. Git objects are not a database backup.

## Constraints for the correction

1. Do not run a blanket revert, rewrite historical migrations, delete master or tariff records, or drop clinical/financial columns. A new additive migration can introduce facility-owned identities and optional references while preserving existing master-era records for historical integrity. The master configuration UI and routes should no longer be an active dependency.
2. A database backup and dependency/row-count review are required before any migration in a real environment. This task has no authorization or connection to run it there. For isolated testing, first create a new synthetic database and a separate pre-migration backup; the destructive historical migration chain is authorized only on that synthetic database.
3. Facility service codes must be unique within a facility, not globally. New services and tariff values come only from explicit facility-administrator input; do not generate, copy, recode or merge historical facility prices, master records or ambiguous mappings automatically.
4. Continue to scope access by tenant and facility, preserve authorization and audits, validate active positive/effective prices, and keep source-level duplicate prevention. Preserve posted invoice snapshots, payments, refunds, reversals, ledgers, clinical records and audit logs.
5. Older source code used generalized string/family matching and could charge at request creation. Restoring that billing behavior verbatim would conflict with the explicit instruction not to charge unconfirmed orders and risks wrong-service pricing. Use only an explicitly selected facility service or explicitly configured exact source identifier; missing/ambiguous prices must remain visible for review while care continues.
6. Preserve clinical actions and valid existing source transactions. A single direct facility-owned service/tariff screen and API should replace the active master workflow; historical master metadata must remain inert unless a later authorized, dependency-checked archive plan proves removal safe.
7. Claims, payer interfaces, finalized invoices, receipts, SHA/private-insurance and accounting use existing tariff IDs and snapshots. They require regression testing; no provider calls or claims are authorized.

This document is a source/history audit, not a claim that any workflow or database migration has been tested on a real facility.
