# Reporting Centre — work-in-progress report matrix

**Date:** 4 November 2026. **Branch:** `arena/e088f11d-afyahub-hmis-kenya`.
This is an interim implementation checkpoint, **not a final acceptance matrix or production release**. The [pre-change baseline](reporting-centre-baseline-2026-11-04.md) documents inspection before implementation. No MedSmart screenshots were supplied, so visual parity is not verified.

The seven-category catalogue contains 144 requested entries. Five catalogue entries share four narrow generators: inventory by category and by store, LPO summaries, and current inpatients (also listed under Records). Invoice printing reuses the existing finalized-invoice workflow. The other catalogue entries are explicitly unavailable; their baseline status below describes existing underlying workflows and is **not** a claim that the centre can generate them. Financial, MOH and payroll outputs remain unavailable where reconciliation, policy or official specifications are missing.

**Scope and limitations:** tenant/facility and enabled/hidden module checks, report/domain permissions, `reports.export`, bounded exports (1,000 rows), paginated live snapshots, and fail-closed report/patient-access audit are implemented for the narrow generators. Exports are actual PDF/Excel files; PDFs fail explicitly for unsupported font glyphs instead of silently changing text. The invoice-cohort legacy overview is permission-gated and explicitly unreconciled. Search terms are not written to the general audit log. Times of historical admissions are shown as recorded; no timezone is inferred. No production data, deployment or migration was used.

**Verification for this checkpoint:** synthetic PostgreSQL + real authenticated HTTP, report-centre UI tests, existing reporting, finalized-invoice and inpatient nursing tests: **5 files / 41 tests passed, 0 failed, 0 skipped**. TypeScript, formatting and the production client/server builds passed; lint passed with 87 warnings and no errors. Production dependency audit found 0 vulnerabilities; full dependency audit reports four moderate development-tool advisories. These tests cover selected scope, permissions, audit rollback, data/filter correctness, pagination, real PDF/Excel content, formula safety, unsupported export text, print requests and selected-facility invoice guard. They do **not** establish complete financial reconciliation, approved print templates, statutory compliance, browser visual parity, a full-suite regression or production UAT. A real-browser reporting-centre run, full coverage suite and Docker bootstrap were **not run for this checkpoint**. An earlier focused run exposed two outdated source-wiring assertions; those assertions were updated to verify the new, stricter domain/module gates and guarded mounting, and the five-file rerun passed. The PDF test parser was changed to a Node 20-compatible version; actual exported Unicode text is still extracted and asserted. One report-audit failure is deliberately injected by a synthetic test and correctly returns an error without returning patient data.
