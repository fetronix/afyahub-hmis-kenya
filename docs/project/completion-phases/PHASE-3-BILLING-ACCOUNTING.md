## Changes, verification and remaining risks

### Facility tariff audit history — **Partial**

- Added `GET /api/facility-tariffs/:id/history` in `src/routes/facility-services.routes.ts` and a client/UI in `src/api/clients/billing.client.ts`, `src/components/modules/FacilityPricingTables.tsx`, `FacilityServicesManager.tsx` and `FacilityTariffHistory.tsx`. This is facility-owned tariff history, not the removed master-tariff history. Master-only legacy rows have no history action. Existing references are preserved.
- The endpoint requires the existing `tariffs.read` permission and facility-administrator role, checks tenant/facility ownership, returns at most 25 recorded events per page, filters historical details to allowed fields, prevents caching and audits access transactionally. A failed access-audit write fails the read closed. Recorded timestamps are database wall times with no inferred timezone. The UI states that missing events do not prove that no change occurred, and reading history does not reprice existing invoices.
- No migration or database schema change was added. In-place tariff updates and incomplete historical events still cannot establish a complete effective-dated price history for recovering an old clinical charge. Import/export and the remaining catalogue requirements are not established.
- `src/tests/integration/phase3-facility-tariff-history.db.spec.ts` covers synthetic PostgreSQL scope, permissions, pagination, legacy data filtering and audit failure; `src/tests/vitest/facility-services-table-ui.spec.tsx` covers the history UI and facility switching.
