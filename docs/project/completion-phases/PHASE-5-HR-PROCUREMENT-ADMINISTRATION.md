## Existing endpoints, permissions and UI

The existing procurement router provides supplier list/create/update/deactivation and purchase-order list/details/create/update, approval, rejection, administrative completion and cancellation. It checks `procurement.read`, `procurement.create`, `procurement.update`, `procurement.approve`, `procurement.reject`, `procurement.complete` and `procurement.delete` as applicable, plus server-resolved facility/tenant scope. The supplier store is tenant-wide. Existing pharmacy routes expose batch listing, expiry summaries and `POST /api/inventory/:id/batches`, gated by `inventory.read` or `inventory.manage`. Staff invitation/role administration and the accounting UI are existing facilities, not a substitute for HR or the missing financial workflows.
